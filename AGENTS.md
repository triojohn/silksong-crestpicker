# CrestPicker — проектные правила

BepInEx 5 плагин для Hollow Knight: Silksong (C#, .NET, Harmony) — список гребней (crests) в диалоге chapel maid в Bonetown. Файлы `.cs`, `.csproj`, `.sln` и мод правятся только по плану задачи; сборка — через `SilksongPath.props` (см. `.example`).

## Оркестрация

Конфиг агентов — `opencode.json` в корне папки. Промпты живут в пакете оркестратора: `C:/aaz_vault/10-projects/opencode-orchestrator/package/agent/`. Здесь их не копируем и не правим.

## Права и владение файлами

- Тестовые файлы принадлежат агенту `tester`: `tests/*`, `test/*`, `*_test.*`, `*.test.*`, `*_spec.*`, `*.spec.*`, `*Tests.cs`, `*Tests/*`.
- Агент `ivan` их не создаёт и не правит. Попытка `edit` отклоняется правами: `Permission denied: edit`. Нужен тест — задача возвращается оркестратору.
- `tester` не правит продуктовый код: его `edit` разрешён только на тестовые пути.
- `scout` пишет только в `plans/`; остальное — чтение.
- Тестовая директория проекта — `CrestPicker.Tests/`: туда пишет только `tester`, `ivan` не пишет вообще. `TESTING.md` и `docs/` принадлежат `tester`.
- Обход через `shell` запрещён: shell не подчиняется правам `edit`, но правка тестов через `Add-Content`, `Set-Content`, `>` — нарушение владения, а не находчивость.

## Планы

План задачи — `plans/NNN-slug.md`. Шаблон: `C:/aaz_vault/10-projects/opencode-orchestrator/templates/plan.md`. План — источник истины для реализации; `ivan` его не правит, расхождение с планом возвращается как блокер.

## Проверка

Статус верификации — только из enum: `passed | failed | not_run | inconclusive`. Утверждение «работает» без вывода команды не принимается.

## Shell-правила

Правила матчатся по строке команды, которую реально исполняет инструмент, а на этой машине перед командой подставляется обёртка `rtk`. Поэтому шаблоны пишем с ведущей `*`: `*git diff *`, а не `git diff *`.

## Сборка и проверка

- `dotnet build -c Release` — сборка, требует `SilksongPath.props` с путём к установке игры (файл gitignored, шаблон `.example`).
- `dotnet test CrestPicker.Tests` — 33 юнит-теста, только `Pure/`, без ссылок на DLL игры.
- Правило: новая логика, которую можно проверить без движка, идёт в `Pure/` и покрывается тестом; живое поведение (сцены, PlayMaker, TMP, Harmony на живых объектах) тестом не покрывается — ручной чек-лист в `TESTING.md`.
- Лог-маркеры для проверки в игре: `[CREST]`, `[SHOPFX]`, `[SHOP] purchase done` → `sent 'Close'` → `window closed`.
