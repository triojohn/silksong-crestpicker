# CrestPicker — требования и технические факты

Документ-реестр для плагина выбора знака в Hollow Knight: Silksong.
Составлен по декомпилу игры (`C:\Users\trioj\AppData\Local\Temp\opencode\silksong\dec`,
временный каталог — при потере дампа факты перепроверять через `ilspycmd`).

- GUID: `io.github.triojohn.crestpicker`
- Процесс: `Hollow Knight Silksong.exe`
- Версия: `0.1.0` (синхронно: `Directory.Build.props` и `Plugin.cs`)
- Состояние кода: каркас, логики нет

Обозначения: **R** — функциональное требование, **X** — запрет,
**F** — проверенный технический факт.

---

## 1. Назначение

При первом визите к улитке-шаману игрок получает выбор знака вместо ванильной
выдачи одного знака. Список — только уже открытые знаки, переключение мгновенное.

Требования ещё не сформулированы по номерам: они появятся вместе с этапом 2
(`PLAN.md`), когда станет известен рабочий путь UI и FSM-хука. До этого момента
единственное действующее требование — каркас собирается и грузится без изменений
в поведении игры.

## 2. Реестр технических фактов (F)

Все пункты проверены по декомпилу `Assembly-CSharp.dll`.

### 2.1 Знаки

| # | Факт |
|---|---|
| F1 | Список всех знаков: `ToolItemManager.GetAllCrests()` |
| F2 | Знак по строковому ID: `ToolItemManager.GetCrestByName(string)` → `ToolCrest` |
| F3 | Открыт ли знак: `ToolCrest.IsUnlocked` (bool) |
| F4 | Ванильная выдача: `ToolCrest.Unlock()` — сам выставляет `IsUnlocked`, слоты и `DisplayNewIndicator`, дёргает ачивки `FIRST_CREST` / `ALL_CRESTS` |
| F5 | Выдача без ачивок: ручная запись `PlayerData.instance.ToolEquips.GetData(id)` / `SetData(id, data)` |
| F6 | Смена знака в рантайме: `ToolItemManager.SetEquippedCrest(id)`, затем обязательно `ToolItemManager.SendEquippedChangedEvent(force: true)` — без второго вызова остаётся мувсет прежнего знака |
| F7 | «Нормальные» знаки = `IsBaseVersion && !IsHidden`; на практике 7 штук |

Строковые ID знаков:

| ID | Знак |
|---|---|
| `Hunter` | Охотница |
| `Reaper` | Жнец |
| `Wanderer` | Странник |
| `Warrior` | Зверь |
| `Witch` | Ведьма |
| `Toolmaster` | Архитектор |
| `Spell` | Шаман |
| `Cursed` | скрытый, в выбор не входит |
| `Cloakless` | скрытый, в выбор не входит |

### 2.2 Диалоги и меню

| # | Факт |
|---|---|
| F8 | Меню с выбором и покупкой как у торговца: `SimpleShopMenu` + `SimpleShopMenuOwner`, колбэк закрытия `ClosedMenu(bool didPurchase, int purchaseIndex)` |
| F9 | Альтернатива: `UISelectionList` / `UISelectionListItem`. Текстового API у элемента нет — подпись ставится в дочерний `TMP_Text` |
| F10 | Только для двух вариантов: `DialogueYesNoBox.Open(...)` |
| F11 | Закрыть ванильный диалог перед показом своего UI: `DialogueBox.EndConversation(returnHud, onBoxHidden)` |

### 2.3 FSM

| # | Факт |
|---|---|
| F12 | FSM-правка адресуется ключом `(sceneName, objectName, fsmName)` в prefix `PlayMakerFSM.Start` |
| F13 | Хелперы FSM — `Silksong.FsmUtil` (NuGet, в проект пока не подключён) |

### 2.4 Валюта (понадобится, если выбор будет платным)

| # | Факт |
|---|---|

## 4. Риск: на раннем сюжете пул выбора равен одному знаку

**Статус: решение владельца не принято.**

На старте сюжета у игрока открыт только `Hunter`. Поскольку список фильтруется по
`ToolCrest.IsUnlocked` (F3), на первом визите к шаману в списке будет один
элемент — мод фактически ничего не даст. Варианты (выбрать до этапа 4):

1. Выдавать все 7 знаков (`Unlock()` по списку F7) с самого начала — выбор
   осмысленный, но ломает прогрессию знаков и выдаёт ачивки `FIRST_CREST` /
   `ALL_CRESTS` досрочно.
2. Не фильтровать по `IsUnlocked`, а выдавать выбранный знак принудительно, через
   ручную запись `ToolEquips` (F5) без ачивок. Тогда «выбор» = «выдать один любой».
3. Оставить фильтр и признать, что мод полезен только на сейвах, где знаки уже
   открыты (поздняя игра).
