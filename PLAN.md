# CrestPicker — план работ

Порядок этапов обязателен: каждый следующий опирается на факты предыдущего.
Технические факты и открытые вопросы — в `REQUIREMENTS.md`.

| Этап | Содержание | Статус |
|---|---|---|
| 0 | Декомпил игры, карта API знаков и диалогов | **готово** |
| 1 | Поиск сцены/объекта/FSM первого улитки-шамана | не начато |
| 2 | Прототип окна выбора без FSM | не начато |
| 3 | Интеграция с улиткой через FSM-хук | не начато |
| 4 | Полировка: тексты, иконки, отказ, повторный визит | не начато |
| 5 | Заглушка ванильной выдачи (отложено) | отложено |

---

## Этап 0 — карта API (готово)

Сделан декомпил `Assembly-CSharp.dll`. Известны: список и фильтрация знаков,
выдача, переключение в рантайме, варианты меню выбора, закрытие ванильного
диалога, работа с валютой, схема FSM-правок. Факты F1–F15 — `REQUIREMENTS.md`,
раздел 2.

## Этап 1 — найти первого улитку-шамана

**Блокер:** в коде игры строк этой сцены нет, нужен дамп ассетов
(AssetRipper или UnityPy) — имена сцен и объектов лежат в сценах/префабах.

Задача: определить, где именно заканчивается ванильный диалог выдачи знака —
предположительно Moss Grotto, Chapel Maid.

**Критерий готовности:** известны `sceneName`, `objectName`, `fsmName` и имя
состояния, в котором диалог завершается. Без этого этап 3 не начинать.

## Этап 2 — прототип окна выбора без FSM

Собрать UI на `UISelectionList` либо `SimpleShopMenu` (`SimpleShopMenu` даёт
нативный вид выбора, но тянет за собой механики торговца; `UISelectionList`
проще, но требует ручной подписи в дочерний `TMP_Text`).

Состав:
- список из 7 «нормальных» знаков (`IsBaseVersion && !IsHidden`);
- фильтр по `ToolCrest.IsUnlocked`;
- выбор → `ToolItemManager.SetEquippedCrest(id)` + `SendEquippedChangedEvent(force: true)`;
- лог выбранного знака.

Триггер для теста — горячая клавиша из конфига (`.cfg` по стандарту проекта:
`triojohn.crestpicker.cfg`, первая секция `[General]`, первый ключ `Enabled`).

**Критерий готовности:** по горячей клавише открывается список, выбор меняет
знак и мувсет сразу, без скамейки и перезагрузки.

## Этап 3 — интеграция с улиткой

Хук на конец ванильного диалога по ключу `(sceneName, objectName, fsmName)` из
этапа 1. Перед показом своего UI закрыть диалог через
`DialogueBox.EndConversation(returnHud, onBoxHidden)`.

Однократность — флаг мода в `PlayerData` либо `IOnceSaveDataMod`; решение
принимается здесь.

**Критерий готовности:** диалог с улиткой заканчивается показом меню выбора,
повторный запуск игры не показывает меню второй раз.

## Этап 4 — полировка

- Тексты: литералы в коде либо ключи локализации (предпочтительно ключи, если
  найдётся подходящий sheet).
- Иконки знаков в списке.
- Кнопка отказа от выбора («нет, спасибо»).
- Повторный визит к улитке ничего не делает.
- Решение по риску «пул из одного знака» (`REQUIREMENTS.md`, раздел 4).

**Критерий готовности:** мод проходим как обычная игра, отказ не ломает сюжет.

## Этап 5 — заглушка ванильной выдачи (отложено)

7 FSM-правок, по одной на место оригинальной выдачи знака. **Только если
понадобится:** v1 не глушит ванильную выдачу, потому что `IsUnlocked` — булев
флаг, и повторная выдача безвредна.

Причина отсрочки: цена — семь хрупких FSM-правок против нулевого выигрыша на
текущем понимании механики.
