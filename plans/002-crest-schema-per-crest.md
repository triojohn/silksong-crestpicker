# 002 — Схема гребня по выбранному гребню (не всегда Reaper)

## 1. Цель

Правая панель «Crest Schema» показывает данные выбранного в списке гребня: свой силуэт, своё число слотов, свои цвета. Для трёх разных гребней (например «Охотница», «Странница», «Жнец») схема визуально различается, и в логе для каждой строки пишется своё имя.

Критерий готовности:

- При выборе трёх разных строк лог содержит три разных имени: `[SCHEMA] built '<имя>' slots=N`, ни в одном случае не `cloned from 'Reaper'`.
- Число слотов в схеме равно `crest.Slots.Count` выбранного гребня.
- Силуэт соответствует `crest.CrestSilhouette` выбранного гребня.
- Занятые/пустые/заблокированные слоты различаются цветом по правилам ванильного `InventoryToolCrest`.
- Переключение строк перестраивает схему без накопления дубликатов (см. T6).

## 2. Границы

Вне задачи:

- Покупка, цены, доступность гребней в магазине.
- Поведение левой панели деталей (описание, цена, кнопка покупки), кроме текста temp-элемента (T2).
- Другие меню и другие FSM-переходы магазина.
- Изменение ванильных классов игры (`InventoryToolCrest`, `InventoryToolCrestSlot`).
- Локализация новых строк — не добавляем.
- Рефакторинг `ShopCrestSchema.cs` вне перечисленных задач.

Разрешённые файлы: `ShopCrestSchema.cs`, `ShopCrestMenu.cs`, новый файл в `Pure/`, точечно конфиг (флаг режима Clone). Тесты — зона `tester`.

## 3. Research

### Почему всегда Reaper

- `ShopCrestSchema.SelectedCrest()` (`ShopCrestSchema.cs:734`) уходит в `SelectedCrestByIndex` (:759), который требует `_selectedIndex`.
- `_selectedIndex` присваивается только в `NoteDetailsIndex` (`ShopCrestSchema.cs:669`). Вызовов `NoteDetailsIndex` в кодовой базе нет (grep: только объявление).
- Итог: `_selectedIndex == -1` всегда, `SelectedCrestByIndex` не срабатывает.
- Фолбэк — сопоставление по тексту панели: `Match` (`ShopCrestSchema.cs:780–803`). Текст панели — ключ локализации, не отображаемое имя, поэтому сопоставление не находит нужный гребень и остаётся первый/дефолтный — Reaper.

### Почему текст панели — ключ, а не имя

- `ShopItem.displayName` — тип `LocalisedString` (`ShopItem.cs:95`), геттер (:206).
- `CreateTemp` пишет `Sheet="TEMP"`, `Key=name` (`ShopItem.cs:585–596`).
- `CopyCrestText` (`ShopCrestMenu.cs:289–300`) пишет `crest.DisplayName` (обычная строка) через `FieldInfo.SetValue` (`ShopCrestMenu.cs:1408–1423`). Тип не совпадает, исключение глотается, поле остаётся `LocalisedString` с ключом.
- Значит для сопоставления нужен либо ключ локализации, либо номер строки.

### Авторитетный источник выбранной строки

- `ShopMenuStock.BuildItemList` (`ShopMenuStock.cs:231–252`) раскладывает строки по `localPosition.y = num` с шагом `yDistance`.
- FSM передаёт номер строки в `GetName(int)`/`GetDesc(int)` (`ShopMenuStock.cs:264–272`), индексируя `availableStock`.
- Это единственный уже существующий и используемый движком номер строки — от него можно идти к гребню.

### Что уже есть для пространственного запасного пути

- `ShopCosmetics.FindSelector()` (`ShopCosmetics.cs:1599–1602`) находит объект `selector` под `Item List Group`. Позиция `selector` по Y даёт текущую строку, если номер строки недоступен.

### Режим Clone

- `ShopCrestSchema.cs:1250–1316`: данных гребня не читает вовсе. Картинка и слоты берутся из сьюченного виджета, поэтому клон воспроизводит Reaper независимо от строки.

### Ванильные правила отрисовки (эталон)

- `InventoryToolCrest.DeselectedColor = (0.5, 0.5, 0.5, 1)` (`InventoryToolCrest.cs:17`).
- `Setup` берёт `CrestSilhouette` (`InventoryToolCrest.cs:169`), позиции слотов — `slot.Position` как `localPosition` (:245).
- `IsLocked = slotInfo.IsLocked && !SaveData.IsUnlocked` (`InventoryToolCrestSlot.cs:303–307`).
- Заблокированный слот: цвет HSV(H, 0, V), масштаб 0.8 (`InventoryToolCrestSlot.cs:741–742`, `:852`).
- `DeselectedColor` применяется к `crestSprite.Color`; силуэт — через `AlphaSelf` (`InventoryToolCrest.cs:514–517`).
- Данные: `ToolCrestsData.SlotData.IsUnlocked` (`ToolCrestsData.cs:12`), `Data.IsUnlocked` (:18). `ToolCrest.CrestSilhouette`/`CrestSprite`/`Slots` (`ToolCrest.cs:120–130`), `SaveData` (:138–148).

### Цепочка, в которую встраиваемся

```
FSM → ShopMenuStock.GetName(int)/GetDesc(int)  (ShopMenuStock.cs:264–272)
    → availableStock[index] → ShopItem (displayName: LocalisedString)
ShopCrestSchema.SelectedCrest() (ShopCrestSchema.cs:734)
    → SelectedCrestByIndex(_selectedIndex)   // всегда -1
    → Match(panelText)                        // ключ ≠ имя → промах
    → fallback Reaper
```

## 5. Задачи

### T1 (M) Определение выбранного гребня по номеру строки

Файлы: `ShopCrestSchema.cs` (новый хук/подписка), `Pure/CrestSchemaSelection.cs` (новый), `ShopCrestMenu.cs` (регистрация хука при открытии меню).

Что сделать:

1. Harmony-хук (postfix) на `ShopMenuStock.GetName(int)` и `GetDesc(int)` (`ShopMenuStock.cs:264–272`): запоминать переданный номер строки в статическое поле (последняя запрошенная строка).
2. Значение номера передавать в `ShopCrestSchema`: `_selectedIndex = row`, после чего `SelectedCrestByIndex` уже работает без изменений.
3. Запасной путь, если номер строки не пришёл: вычислить индекс по Y. Вынести в `Pure/` чистую функцию `PickRowIndex(float selectorY, float[] rowYs)` — возвращает индекс ближайшей строки в пределах допуска (`Math.Abs(rowYs[i] - selectorY) <= tolerance`, tolerance = половина шага `yDistance`), иначе `-1`.
4. `selectorY` брать из `ShopCosmetics.FindSelector()` (`ShopCosmetics.cs:1599–1602`); `rowYs` — из раскладки `BuildItemList` (`ShopMenuStock.cs:231–252`).
5. Сопоставление по тексту (`Match`, `ShopCrestSchema.cs:780–803`) оставить последним фолбэком, но только после промаха по индексу; логировать, какой путь сработал.

Критерий приёмки:

- При выборе любой строки в логе виден номер строки и выбранное имя гребня, для трёх разных строк — три разных имени.
- `PickRowIndex` покрыт тестами: точное совпадение, между строками, вне допуска (`-1`), пустой массив (`-1`), одна строка.
- При отсутствии хука (номер не пришёл) срабатывает путь по Y, а не Reaper.

Риск регрессии: хук на `GetName`/`GetDesc` вызывается и для других меню магазина. Смягчение: включать запоминание только пока открыта панель схемы гребней (флаг из `ShopCrestMenu`), иначе игнорировать.

### T2 (S) Текст temp-элемента через `LocalisedString`

Файлы: `ShopCrestMenu.cs` (`CopyCrestText`, :289–300; `FieldInfo.SetValue`, :1408–1423).

Что сделать:

1. При записи имени не подменять `LocalisedString` строкой. Либо писать корректный `LocalisedString { Sheet = "TEMP", Key = name }` по образцу `ShopItem.CreateTemp` (`ShopItem.cs:585–596`), либо не писать вовсе и брать текст из существующего `ShopItem`.
2. Убрать проглатывание исключения в месте записи: логировать неудачу с типом поля и типом значения.
3. Проверить, что `crest.DisplayName` не используется как ключ локализации.

Критерий приёмки:

- В логе `[SCHEMA]` видно читаемое имя гребня, совпадающее с `crest.DisplayName`, без исключений в логе.
- Ни одного `Exception`/`TargetException` в логе при открытии панели.

Риск регрессии: temp-элемент используется и левой панелью. Смягчение: менять только поле `displayName`, остальные поля не трогать.

### T3 (S) Силуэт от данных гребня

Файлы: `ShopCrestSchema.cs` (режим построения из данных).

Что сделать:

1. Спрайт силуэта брать из `crest.CrestSilhouette` (`ToolCrest.cs:120–130`), а не из сьюченного виджета.
2. Альфа 1 и цвет по правилу ванильного `DeselectedColor` (`InventoryToolCrest.cs:17`, `:514–517`): силуэт через `AlphaSelf`, чтобы не перекрашивать в серый полностью.
3. `crest.CrestSprite` применять только если гребень надет (иначе силуэт).

Критерий приёмки:

- Для трёх разных гребней в логе три разных имени силуэта/спрайта, картинки визуально различаются (ручная проверка).
- Надетый гребень показывает `CrestSprite`, ненадетый — силуэт.

Риск регрессии: у части гребней `CrestSilhouette` может быть `null`. Смягчение: фолбэк на `CrestSprite`, затем на текущий спрайт виджета с логом `[SCHEMA] silhouette fallback '<имя>'`.

### T4 (M) Слоты от `crest.Slots`

Файлы: `ShopCrestSchema.cs`, при необходимости новый `Pure/CrestSlotStyle.cs`.

Что сделать:

1. Число и позиции слотов — из `crest.Slots` (`ToolCrest.cs:120–130`), позиция — `slot.Position` как `localPosition` (эталон `InventoryToolCrest.cs:245`).
2. `IsLocked = slot.IsLocked && !crest.SaveData.IsUnlocked` (`InventoryToolCrestSlot.cs:303–307`, данные `ToolCrestsData.cs:12`, `:18`).
3. Цвет незаблокированного слота — `UI.GetToolTypeColor(type)`; заблокированного — HSV(H, 0, V) и масштаб 0.8 (`InventoryToolCrestSlot.cs:741–742`, `:852`).
4. Спрайт типа слота — `templateSlots[(int)type].slotTypeSprite`; если индекса нет — сгенерированный кружок плюс лог `[SCHEMA] slot sprite generated type=N`.
5. Чистую часть (маппинг тип→цвет/масштаб/флаг) вынести в `Pure/` для тестов, если она не требует Unity-типов.

Критерий приёмки:

- Число видимых слотов равно `crest.Slots.Count` для трёх разных гребней.
- Заблокированный слот серый (S=0) и уменьшен (0.8), незаблокированный — цвет типа.
- Нет исключений при гребне с большим числом слотов.

Риск регрессии: выход за границы панели при большом числе слотов. Смягчение: не менять размеры панели, лишние слоты логировать `[SCHEMA] slots clipped: have=N shown=M` и не создавать.

### T5 (S) Режим Clone

Файлы: `ShopCrestSchema.cs:1250–1316`, конфиг.

Что сделать:

1. Выключить режим Clone по умолчанию (флаг в конфиге, значение `false`), обоснование: режим не читает данные гребня и по определению воспроизводит сьюченный виджет — он и есть источник бага.

3. Основной путь построения — из данных (T3, T4).

Критерий приёмки:

- При дефолтном конфиге ни одного лога `clone mode`.
- При включённом флаге поведение прежнее (клон), лог явно это сообщает.

Риск регрессии: кто-то полагается на клон визуально. Смягчение: флаг возвращает старое поведение без правок кода.

### T6 (S) Кэш и перестройка при смене строки

Файлы: `ShopCrestSchema.cs`.

Что сделать:

1. При изменении выбранного индекса полностью пересобирать схему, уничтожая прежние созданные объекты (не оставлять дубликаты в иерархии).
2. Кэш по имени/индексу гребня: повторный вход в ту же строку не пересобирает.
3. Лог `[SCHEMA] built '<имя>' slots=N` на каждую успешную сборку; `[SCHEMA] cache hit '<имя>'` на попадание.

Критерий приёмки:

- После N переключений строк в иерархии ровно один набор объектов схемы (ручная проверка).
- Лог: N разных `built` для N разных строк, без роста числа объектов.

Риск регрессии: утечка объектов при быстрых переключениях. Смягчение: пересборка синхронно в одном обработчике, уничтожение до создания новых.

## 6. Стратегия тестов

Тестами покрывается только `Pure/`:

- `PickRowIndex(selectorY, rowYs)` — точное совпадение, середина между строками, вне допуска → `-1`, пустой массив → `-1`, одна строка, граничное значение допуска.
- Маппинг слота (если вынесен): locked → S=0 и масштаб 0.8; unlocked → цвет типа; тип без спрайта → флаг «сгенерировать».

Файлы: `CrestPicker.Tests/Pure/CrestSchemaSelectionTests.cs`, при выносе маппинга — `CrestPicker.Tests/Pure/CrestSlotStyleTests.cs` (создаёт `tester`).

Команда: `dotnet test CrestPicker.Tests`.

Не проверяется юнит-тестами:

- Рендер TMP (силуэт, цвета, размеры) — глазная проверка в игре.
- Переходы PlayMaker (`GetName`/`GetDesc`, `Close`, переходы панелей).
- Фактическое положение `selector` и строк в живом UI.

Ручной чек-лист (в `TESTING.md`, зона `tester`):

1. Открыть магазин, панель схемы, выбрать «Охотница» — силуэт, слоты, цвета соответствуют.
2. Выбрать «Странница» — схема отличается.
3. Выбрать «Жнец» — схема отличается, имя в логе своё.
4. Многократно переключать строки — нет дубликатов объектов.
5. Надеть гребень, открыть магазин — надетый показывает `CrestSprite`.

## 7. Риски

- Хук на `GetName`/`GetDesc` ловит чужие меню — вероятность средняя, последствие: неверный индекс. Смягчение: флаг «панель схемы открыта», иначе игнорировать.
- `_selectedIndex` ставится асинхронно относительно отрисовки — вероятность средняя, последствие: первая отрисовка со старым гребнем. Смягчение: перерисовка по факту установки индекса (T6).
- `CrestSilhouette == null` — вероятность средняя, последствие: пустая картинка. Смягчение: фолбэк `CrestSprite` → спрайт виджета с логом.
- Большое число слотов не влезает в панель — вероятность низкая, последствие: обрезка. Смягчение: лог обрезки, без изменения размеров панели.
- Тип поля `displayName` отличается от ожидаемого в другой версии игры — вероятность низкая, последствие: исключение при записи. Смягчение: проверка типа перед `SetValue`, лог с типами.
- Режим Clone используется снаружи — вероятность низкая, последствие: смена вида по умолчанию. Смягчение: флаг возвращает старое поведение.
